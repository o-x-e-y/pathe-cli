# `where` and favourites — design

**Date:** 2026-09-09

## Problem

Two gaps found while answering "where can I see *Leviticus*?".

Asking that question today means naming cinemas you already suspect. To get a
national answer you have to scrape all 31 slugs out of `pathe cinemas` and paste
them into `-c`, which costs 31 matrix requests plus the showtimes fanout (~15 s
cold) and prints 337 lines, 22 of whose sections are
`_Geen voorstellingen gevonden._`. The answer is in there; you have to fish it
out.

Separately, the cinemas that count as "yours" are hard-coded in `config.py`.
`PATHE_CINEMAS` overrides them per shell, but there is no declarative place to
put them — which is what a NixOS user wants.

## API discovery

`GET /api/show/{slug}/cinemas` exists and is the exact inverse of the
`/api/cinema/{slug}/shows` matrix the tool already leans on. Verified against
the live API on 2026-09-09:

- Returns an object keyed by cinema slug, containing **only** the cinemas where
  the title plays. For `leviticus-53403`: 9 keys, matching a 31-cinema fanout
  exactly.
- Each value is `{"days": {"YYYY-MM-DD": {"tags": [...], "versions": [...],
  "specialShowtime": bool, ...}}, "releasedAt": "YYYY-MM-DD"}` — the same cell
  shape as the cinema matrix, so `tags` and `versions` are available without a
  second request.
- Covers the whole published horizon in one request.
- An unknown slug returns `200` with `{}`, not `404`. There is no error tail to
  handle, only an empty one.

So the gap was never in the API. One request replaces thirty-one.

## Decisions

**A new `where` command, not an overloaded `film`.** `film` answers "when",
`where` answers "where"; the useful sequence is `where` to see the field, then
`film -c <picked>` for times at the two or three you care about. Folding both
into `film` would make the same invocation mean different things depending on
whether `-c` was given.

**`where` does not filter.** Same rule as `film`: asking for a title by name
means you want that title, dub or not.

**Gaps in a run are printed, not smoothed.** A date span alone would claim
Zwolle plays Leviticus for seven days when it plays five. When the number of
days is short of the span, the count is shown.

**Favourites replace the built-in default rather than adding a second tier.**
One list, one concept. The hard-coded four stay only as the no-config fallback.

**The env var beats the config file.** `settings.json` is declarative and
permanent; `PATHE_CINEMAS` is the ad-hoc override for one shell, so it is the
more specific signal and wins.

**Malformed `settings.json` is fatal.** The file is machine-generated by Nix. A
broken one is a bug to surface, not something to silently fall back from.

**Options live in the flake, values in the consuming config.** `pathe-cli`
exports a home-manager module defining `programs.pathe`; `~/nixos` imports it
via `home-manager.sharedModules` and only sets values. Anyone else consuming the
flake gets the same options, opt-in (`enable` defaults false).

## Design

### `pathe where <titel>`

```
# Leviticus — 9 van 31 bioscopen
88 min · -16 jaar · Horror

## Jouw bioscopen
  `pathe-tilburg-stappegoor`
     Pathé Tilburg Stappegoor   wo 9 – wo 16 sep
  niet in: helmond, eindhoven, tilburg-centrum

## Elders (8)
  `pathe-amsterdam-noord`
     Pathé Amsterdam-Noord      wo 9 – wo 16 sep
  ...
  `pathe-zwolle`
     Pathé Zwolle               wo 9 – di 15 sep (5 dagen)
```

- `api.PatheClient.show_cinemas(slug)` → `/show/{slug}/cinemas`, `CATALOGUE_TTL`.
- `queries.where(client, query, favorites, dates, *, only_favorites=False)`:
  resolve the title through `catalogue.search` (first hit, as `film` does),
  one `show_cinemas` call, one `cinemas` call for names, split and sort.
- Favourites keep the order they are configured in; the rest sort by city then
  name, as `list_cinemas` already does.
- `niet in:` names the favourites that do *not* have it, so an empty first
  section is unambiguous.
- `--days` / `--from` narrow the window, defaults as `film` (60, today).
- No hits for the title → the existing empty-search section. Title found but no
  cinemas → an explicit "draait nergens in dit venster".
- Further title matches → the same `ook gevonden:` note `film` emits.
- All formatting in `render.py`.

### Favourites

`config.py`:

- `settings_path()` — `$XDG_CONFIG_HOME/pathe/settings.json`, falling back to
  `~/.config/pathe/settings.json`. (`pathe`, not `pathe-cli`, to match the
  existing `~/.cache/pathe`.)
- `load_settings()` — `{}` when absent; `PatheError` naming the path when the
  JSON is malformed or not an object. Unknown keys are ignored.
- `favorites()` — `settings.json` `favorites`, else `DEFAULT_CINEMAS`.
- `default_cinemas()` — `PATHE_CINEMAS`, else `favorites()`.

Resolution is unchanged: entries go through the existing `resolve()`, so
`"stappegoor"`, `"pathe-tilburg-stappegoor"` and `"Tilburg Stappegoor"` all
work and a typo still produces the `onbekende bioscoop` error.

File shape:

```json
{ "favorites": ["pathe-helmond", "pathe-eindhoven",
                "pathe-tilburg-centrum", "pathe-tilburg-stappegoor"] }
```

### `-f` / `--favorites`

Global flag, alongside `-c` in `_global_flags()`. Means *the favourites from the
config file, whatever the environment says* — so it still does something with
`PATHE_CINEMAS` set. On `where` it drops the `Elders` section. `-c` together
with `-f` is an error, not a silent winner.

### NixOS

| where | what |
|---|---|
| `nix/hm-module.nix` | new: `programs.pathe.{enable,package,favorites}`, `enable` default `false`; writes `xdg.configFile."pathe/settings.json"` only when `favorites != []` |
| `flake.nix` | `homeManagerModules.default` alongside `overlays.default` |
| `~/nixos/flake.nix` | add it to `home-manager.sharedModules` |
| `~/nixos/home/programs/pathe/` | new: `apps.pathe.enable` (default true) → sets `programs.pathe` |
| `~/nixos/home/programs/default.nix` | `./pathe` |
| `~/nixos/home/programs/claude-code/pathe/` | drop `home.packages`; keep the slash command and permission |

The split exists because `pathe` currently disappears from the system when
claude-code is disabled, which is the wrong dependency.

## Testing

Offline, as the rest of the suite is. New fixtures recorded from the live API
on 2026-09-09: `/show/leviticus-53403/cinemas` and an unknown slug's `{}`.

- `where`: favourites present, favourites absent, `--days` narrowing, gap-count
  rendering, unknown title, title with no cinemas, `-f` dropping `Elders`.
- config: missing file, malformed file, non-object file, precedence across
  `-c` / `PATHE_CINEMAS` / `settings.json` / built-in.
- CLI: `-c` and `-f` together errors; `-f` survives being given on either side
  of the subcommand (the `SUPPRESS` trap `CLAUDE.md` documents).
